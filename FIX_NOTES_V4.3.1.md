# GeoPilot AI 4.3.1 — POI fallback and EV marker interaction patch

## Fixed

### HERE Search outage / empty result behavior
- Nearby and route POI searches use HERE Search first.
- If HERE fails or returns no matches, GeoPilot tries live OpenStreetMap / Overpass for supported category tags.
- Fallback records keep their real provider source, coordinates, names, and calculated geographic distance; UI labels no longer claim OSM records came from HERE.
- Tourist-attraction fallback omits unnamed OSM features so a named attraction list does not display placeholders.
- When both providers are unavailable, the backend returns an outage message and empty verified-results collection. The LLM is bypassed for spatial listings and cannot add unverified names, distances, coordinates, or map pins.

### EV charging-station map interaction
- Makes visible marker DOM clones explicitly interactive for mouse/touch and keyboard input.
- Adds capture-phase click delegation on the map container keyed to each cloned marker, alongside native pointer and HERE tap handling. This avoids relying on just one HERE DOM-marker event path.
- Deduplicates the click/tap/pointer events generated by one physical action.
- Clicking a charging marker now also selects a station-details panel containing the station name, operator, coordinates, route distance, planned stop index, and source. This panel remains useful if the HERE info bubble cannot open.
- General POI popup/detail source labels are dynamic instead of hard-coded as HERE.

### Frontend checks
- Removes unused local/property declarations that trigger the frontend's `noUnusedLocals` build option.

## Validation

- TypeScript strict-ish check on the changed App/map adapter using temporary ambient React declarations: passed with `noUnusedLocals` and `noUnusedParameters`; a complete Vite production build could not be completed because `npm ci` stalled while fetching packages in this environment.
- Live HERE Search, OpenStreetMap/Overpass, and browser marker interactions have not been exercised end-to-end from this environment. The fallback paths have unit tests; please run the three UI checks below in your local environment.

   - Expected: HERE results first, otherwise real OSM/Overpass results with accurate source labeling; never an LLM-generated table of approximate distances/coordinates.
2. Click each numbered EV charging marker on the map.
   - Expected: map information bubble opens and a selected-station detail panel appears.
3. Temporarily use an invalid HERE Search key while keeping `OVERPASS_URL` reachable.
